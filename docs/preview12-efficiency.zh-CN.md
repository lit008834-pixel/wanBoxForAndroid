## 重载生命周期

规则编辑先正常写入 Room，再发出重载请求；App 生命周期范围持有单一接收任务，没有定时空转。400ms 内连续请求合并成一次，取的是应用时最新数据库状态，不保留第一次编辑的旧配置。显式连接/停止仍使用原控制入口，不延迟停止；停止后待处理编辑只应用快照，不能重新启动核心。错误只显示既有安全错误码；取消和校验失败不伪装成功。

同样内容再次提交仍由模块判断，不重新 stage、替换 previous 或重启当前进程。生成配置/复制资源可能仍有成本，本次不宣称消除了所有 App 端生成开销。持续编辑且中间静默超过 400ms 可产生多次提交；已有连接在真实配置切换时仍可能短暂断流。

## 规则优先级边界

核心 DNS 劫持、IPv4/IPv6 限制、DNS bootstrap、防回环与用户启用的局域网绕过保持原顺序，不能被普通用户规则覆盖后产生核心回环或 DNS 泄漏。**规则模式**中，用户显式规则先执行，其次为只有规则集条件的宽泛规则，最后是内置 fallback/final；每层按拖动排序执行。该优先级是本版明确的行为变化：原来排在首位的宽泛规则集不再遮蔽后面的显式规则。带额外匹配条件或自定义 JSON 的规则集保留在显式层，避免丢失 invert/高级条件。**全局模式**保持原有全部代理语义；完整自定义 JSON 保持用户自己的规则顺序。没有把“用户最高”解释成绕过系统安全规则或改变全局模式。
