# 输入法直连移入路由

作者：@author 雾晚

适用范围：本文记录提交 `74f7efe`（2026-10-05）的迁移变更；该变更已包含于 2026-10-06 的仓库基线 `v3.0.7-preview.5`。下文的用户日志与验证是该次变更记录，不代表之后的设备状态或语音识别已获验证。

## 本次范围

- 移除设置页独立的“当前输入法直连”开关和临时配置注入。
- 旧选项存在时，将当前输入法保存成普通应用直连规则；保持原启用状态，放在已有用户规则之前，其他规则的 ID、内容和相对顺序不变。
- 在“路由”页编辑、启停、排序或删除该规则；删除后不会自动重新创建。切换输入法时，可在该规则的应用选择器中重新选择。
- 遵循现有规则模式、全局模式和完整自定义配置行为，不再设置独立于用户规则的隐藏优先级。
- 路由保存、删除、启停和排序后，在服务运行时重启服务以重建配置；避免节点选择器的快速切换仅重载节点而漏掉路由更新。

## 兼容性

不更改 Room schema、包名、签名、核心版本、VPN/Root TUN 参数或用户 DNS 默认值。转换在规则数据库事务中执行，事务提交后才删除旧偏好；中途退出再次执行不会重复创建等价规则，也不会开启用户已经禁用的等价规则。无法识别当前输入法时保留旧偏好，等待后续正常读取。

备份使用已有 rules 字段，不保存源手机的输入法 UID；在目标手机由现有应用规则生成器重新映射包名和 UID。

## 语音问题的记录

用户提供的第二份日志确认旧选项已开启。本机 Clash API 的实时连接显示搜狗语音服务器请求命中了 package/UID 直连规则，并有双向数据；这不等于语音识别成功。用户随后将范围收窄为移除按钮并发布新版，因此本次不宣称已修复语音识别失败。

## 验证

纯规则测试覆盖身份校验、启用状态和等价规则判断；界面契约检查确保旧设置入口消失。仪器测试覆盖事务转换、重复转换、已有禁用规则、删除后不再生成，以及 VPN/Root TUN 和 Fake-IP 配置由固定核心接受。仪器测试仅在测试环境运行，不在用户手机清空或替换数据库。
