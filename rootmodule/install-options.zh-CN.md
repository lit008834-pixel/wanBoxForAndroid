# 安装器选择数据方式与管理 APK

作者：雾晚。配套版本：3.0.7-preview.10；基于 preview.9 完成安装器选项，不改写 preview.9 标签或产物。

## 操作

- 音量上循环切换；音量下确认。首次 10 秒未操作采用默认项；切换后 20 秒未确认取消安装。按键不可读取时取消，不能把读取失败当成确认。
- 数据方式：保留全部（默认）、仅保留节点和订阅、全新安装。后两项需再次按音量下确认；音量上或超时取消，不改用户数据。
- 带 APK 的包：未安装管理 App 时显示安装，已安装时显示覆盖更新；也可跳过。覆盖安装使用 PackageManager `install -r`，不先卸载，不清空 App 数据。失败可手动安装配套 APK。
- 不带 APK 的包：不尝试安装 APK。选择仅节点或全新安装时，需要自行更新配套管理 APK。
- 不再提供 App 内「模块更新数据」按钮或重复的选择弹窗，其他界面不变。

## 数据边界和时序

wanBox 的全部节点、分组与订阅由管理 App 的 Room 数据库持有，模块仅保存运行快照。与 NetProxy 的模块 Catalog 不同，安装器不能通过复制模块目录保留全部订阅，也不直接修改 App SQLite 或执行 `pm clear`。

1. 安装器校验暂存包，将已确认方式和包指纹写入 root 管理的暂存目录。后台任务仍等待管理器退出再热切换；标准开机更新也会读取同一选择，不因超时或重启丢失。
2. 保留全部不创建数据重置请求，沿用已有运行恢复行为。仅节点/全新安装只生成随机令牌的待处理记录，停止旧核心且不自启旧快照；数据暂时保留。
3. 配套管理 App 第一次打开或连接时读取模块 CLI 状态。先生成并校验完整便携 JSON 备份和 App 原子日志，再按既有模块归档与 Room 事务应用已确认的方式。
4. 仅节点保留 profiles、groups（含订阅），清除 rules、settings 和旧模块运行配置；全新安装清空这四部分及旧模块运行配置。保留旧 ID/分组关系，数据库 schema 不变。
5. 模块归档和 Room 写入完成后，以相同令牌确认并删除待处理记录，同时保存完成记录。热更新与开机使用同一令牌，避免热更新后暂存包残留、再次重启时重新清除新数据。未完成时禁止连接；重复打开自动继续原备份，不以半清空数据库重新生成备份。过期令牌、替换后的包、损坏记录不会清除新的选择。

因此安装页面选择立即生效为待处理任务，**App 数据的安全处理发生在配套新版 App 首次打开时**；不能把安装日志完成当成 Room 已处理。跳过/缺少新版 APK 时维持暂停连接，更新并打开配套 APK 后继续。不会新增后台广播入口或代替用户启动 App。

完整 App 备份保留于 App 私有 `files/module-update-backups/OwnBox_backup_*.json`，模块归档保留于 `/data/adb/wanbox/archives/`，不会自动删除。需要恢复时可使用 Root 文件管理器复制 JSON 到 SAF 可选位置，再通过现有工具页备份导入；不要公开备份，内容可能包含凭据。
